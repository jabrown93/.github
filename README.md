# jabrown93/.github

User-level defaults shared across all `jabrown93` repositories: issue/PR
templates, community health files ([`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md),
[`CONTRIBUTING.md`](CONTRIBUTING.md), [`SECURITY.md`](SECURITY.md)), and the
shared Renovate preset.

- **Renovate** — shared preset in [`renovate-config.json`](renovate-config.json),
  consumed via `"extends": ["github>jabrown93/.github//renovate-config.json"]`.

### `constraints.npm`

The preset pins Renovate's npm to `>=11.6.2`. JSON carries no comments, so the
reason lives here: npm **11.6.1 and older drops optional dependencies whose
`os`/`cpu` cannot match the build host** when it writes a lockfile, while
leaving the parent's `optionalDependencies` requirement in place. `npm ci` then
refuses the result (`EUSAGE … Missing: <pkg> from lock file`).

Without the constraint Renovate resolves npm from each repo's `engines.node`;
a floor of `^22.12.0` selects Node 22, whose bundled npm is 10.9.x, so every
`:maintainLockFilesWeekly` run rewrote a lockfile that CI could not install.
Observed in the homebridge plugins: `@rolldown/binding-android-arm64`
(`os: ["android"]`) and `@rolldown/binding-wasm32-wasi` were stripped on each
lock-file-maintenance commit, breaking the `sbom` job until the lock was
regenerated by hand.

## CI library

The reusable GitHub Actions workflows and composite actions that used to live
here (`node-build`, `codeql`, `stale`, `npm-release`, `docker-release`,
`generate-sbom`) have moved to
[`jabrown93/ci`](https://github.com/jabrown93/ci). That repo versions each
component independently (release-please, `<component>-vX.Y.Z` tags) instead of
one shared stream — see its README for usage and pinning.

This repo has no reusable workflows, no composite actions, and no release
automation of its own: nothing here is versioned, and there is no runtime
code.
